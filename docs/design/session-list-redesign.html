1. 背景与问题

anureo 当前有两条对外会话列表方法：标准 ACP session/list 与 anureo Desk 的 canonical _anureo.dev/session/list；迁移期仍保留 list-global alias。三者共享 SessionIndex/repository 核心，legacy alias 只负责旧字段投影和 boolean archived 适配。

WHERE COALESCE(updated_at, created_at) < ?cursor
ORDER BY COALESCE(updated_at, created_at) DESC

单个 updated_at 不是完整总序：相同时间戳跨页时会跳过记录；分页期间的活动、归档或恢复会造成重复或遗漏。标题、归档、恢复和 lifecycle 也复用 updated_at，把管理操作误解为“最近对话”。全局列表还没有可靠的父子关系。

2. 目标：要完成的事情

本次改造要把 anureo 的 session list 从“以 updated_at 临时拼出的全局列表”，升级为由 SessionIndex 驱动、支持稳定分页和实时合并的正式能力；同时让 anureo Desk 只依赖一个明确的私有列表契约，并在迁移期兼容旧版本。完成后，列表的集合、顺序、层级和实时状态都由服务端强语义决定，客户端不再通过时间戳、标题或事件先后顺序猜测。

3. 目标数据模型

-- 另建 owner current_version 与 durable tombstone tables

统一 mutation 明确覆盖 create、activity、archive/restore、lifecycle、metadata、内部 repair reparent 和 delete。每个非 history-replay prompt 被接受时至多记录一次 Activity；token/part/tool progress 不写 index。管理操作不改 activity，但 archive/delete/reparent 会重算旧、新祖先。lifecycle 只使用 durable idle/closed，live busy 状态留在标准 ACP 链路；public API 不提供 reparent。

tree_activity_at 是自身和沿全 active parent edges 可达后代的最大 activity，不是历史 high-water；closed 但未 archived 的记录仍计入，archived parent 会切断上方 tree。

活跃 effective root 顺序为 tree_activity_at DESC, session_id ASC；子节点为 activity_at DESC, session_id ASC；归档视图为 archived_at DESC, session_id ASC。parent 已归档/删除或缺失时，active child 临时作为 root 保持可见，parent 恢复后按持久化 parent 自动挂回。

4. _anureo.dev/session/list 与实时事件

不另建版本化的新方法。直接升级现有实现，最终 wire method 改名为 _anureo.dev/session/list。它与标准 ACP session/list 不冲突：标准方法走 ACP handler，私有方法走 extension registry。

{ "archived": "all", "directory": "C:/repo", "limit": 200 }

{
  "sessions": [{
    "sessionId": "ses_123", "parentSessionId": null,
    "cwd": "C:/repo", "title": "...", "createdAt": "...",
    "activityAt": "...", "treeActivityAt": "...",
    "stateChangedAt": null, "metadataUpdatedAt": "...",
    "archivedAt": null, "closedAt": null, "lifecycle": "idle",
    "metadata": {}, "revision": 42, "indexVersion": 108
  }],
  "nextCursor": "opaque", "hasMore": true, "snapshotVersion": 108
}

archived 为 all/active/archived 枚举；Desk full/directory load 使用 all。snapshot identity、下一位置、cursor version 与 filter hash 封装在 HMAC cursor；snapshot 冻结完整 projection 与 owner snapshotVersion。过期返回 snapshot_expired，容量不足返回 snapshot_capacity_exceeded，都不能解释为空列表。

all 的序列是 active tree 的稳定 pre-order traversal，随后追加 archived records；hasMore 与 nextCursor 必须同步。兼容 list-global 共享同一 query/snapshot core，但保留旧 boolean filter 和 updatedAt projection；不能把新 record 原样返回给旧 Desk。

成功完成的 snapshot 对其 owner/directory scope 具有 authoritative absence：原子 commit 删除 scope 内缺席的旧记录，保留 scope 外和失败 scope；随后按 revision 合并 event/tombstone overlay，再叠加 optimistic shadow。

{ "topic": "session", "event": {
  "type": "session.updated",
  "properties": { "info": { "sessionId": "ses_123", "revision": 42 } }
}}

真实 transport envelope 是嵌套的 {topic,event:{type,properties}}。created/updated 使用完整 record；deleted tombstone 包含 cwd/parent/revision/indexVersion/deletedAt。当前逐标准 update 的 minimal event 必须移除。Global bus 是 fire-and-forget：drop 不回滚 DB，actor 用 response 收敛，其他 client 由集中 60 秒 authoritative resync 修复。

标准方法负责 active ACP projection，并为旧 client 固定一次返回全部记录、nextCursor=null；私有方法负责 snapshot/index fields。

4.1 已冻结的实现参数

维度不可变实现契约
version空 owner snapshotVersion=0，第一次真实 mutation=1；record revision/indexVersion 从 1 开始。全部是 checked JSON safe integer，每个真实 owner transaction 只分配一个 indexVersion，溢出整体回滚。
snapshot进程内 immutable；5 分钟不续期；4/owner、64 MiB/owner、256 MiB/process；过期清理后 LRU，tie-break snapshot ID。
cursor128-bit snapshot ID、进程 256-bit secret、HMAC-SHA256、最大 1024 bytes；restart → snapshot_expired。
activity/no-opbusy lease 后、executor 前提交；validation/busy/replay 不写，cancel/failure 保留一次；相同 metadata/archive/lifecycle 不增 version/event。
timeUTC RFC 3339 固定 6 位小数；新字段值取 max(now 截断到微秒, previous+1µs)，系统时钟回拨不得造成 mutation 时间倒退。
migrationBEGIN IMMEDIATE 原子 backfill；metadata table 重建为 ON DELETE CASCADE，每 connection foreign_keys=ON，orphan 清理后 foreign_key_check。
deleteresponse _meta 返回永久紧凑 tombstone；重复 delete 返回原值，ID 永不复用；client 仅由覆盖版本的 owner-wide snapshot 清 tombstone。

新协议的 full load 与 directory refresh 都使用单个 archived="all" snapshot，再按 archivedAt 派生两个 view。只有完整成功后才 scoped replace；失败/过期保留旧 cache。snapshot 加载期间的事件和 tombstone 作为 overlay 原子合并。archive/delete 成功同步更新 global membership、directory projection 和 selection；失败从 shadow snapshot 回滚。

5.4 Canonical record 与统一排序

新增强类型 SessionIndexRecord 保存 parent、activity/tree/state/metadata 时间、archive 与 revision。time.updated = activityAt 仅作为 legacy UI 兼容映射，treeActivityAt 独立保存；非法或缺失时间不得用 Date.now() 填充。unversioned directory event 只能更新聊天实时字段，不能覆盖 versioned index 字段。

共享 activity/rank helper 必须覆盖 Sidebar、Recent、worktree grouping、session row、retention、edge swipe、Tray、mobile widget、MobileSessionsSheet、MobileSessionStatusBar、SessionSwitcher 和 Command Palette，避免不同视图自行用 time.updated 得出不同顺序。

5.5 Capability、fallback 与 retry

  1. capability 明确支持 list：调用新方法。
  2. 明确只有 list-global：直接调用 alias。
  3. capability 不可判定：先试新方法，仅 JSON-RPC -32601 回退。
  4. -32001 表示 extension 域不存在，不能 fallback；权限、DB、invalid cursor、snapshot expired 同样不得 fallback。
  5. 只有 transient transport/readiness 错误重试；移除当前 retryIf: () => true。

现有 ACP runtime 已保存 anureo 在 agentCapabilities._meta["anureo.dev"].session.methods 中发布的能力，因此不需要新增 RuntimeAPI、Web route、Electron IPC 或 VS Code bridge。

6.1 实际迁移、校验与回滚手册

当前没有独立 migration CLI。anureoAcpAgent::new 创建 SessionRepository 时自动执行 ensure_schema()；数据库通常是 {ANUREO_HOME}/memory.db。发布时必须先停掉所有 ACP writer，再备份主文件及存在的 -wal/-shm sidecar，随后只启动一个新版本 ACP 触发 migration。

  1. 记录实际 ANUREO_HOME 和数据库绝对路径，停止 ACP/Desk host 并确认无并发 writer。
  2. 保存带版本和 UTC 时间的 SQLite 备份；不要在进程运行时直接复制主文件。
  3. 启动新 ACP，确认 initialize 成功；只读连接检查新增 columns、acp_session_index_state、acp_session_tombstones 和 PRAGMA foreign_key_check 零行。
  4. 执行 cargo test -p anureo-acp --lib -- --test-threads=1、cargo check -p anureo-acp --lib 和 clippy，并保存命令、commit、备份名与输出。
  5. 失败时保留失败数据库和日志，停止 ACP，从完整备份恢复后再启动旧版本；不要手工删除新列/表或在原文件上反复重试。
  6. 回滚后重新做完整性检查及 session/list、session/load、session/delete 验证；Desk 需要 runtime switch/reconnect authoritative resync，因为数据库备份不能撤销已发出的事件或本地缓存。

ACP wire-level E2E harness 支持 ANUREO_ACP_BINARY 指定独立构建的 anureo executable；每个版本必须使用独立 ANUREO_HOME，保存 capability、canonical/legacy list 请求序列和错误响应。真实多版本 Desk/anureo 组合仍需发布环境联调留档。

scripts/run-session-list-compat.ps1 -NewanureoBinary <PATH> [-OldanureoBinary <PATH>] [-OutputDir <DIR>] 默认逐个设置 ANUREO_ACP_BINARY 并运行不依赖模型的 e2e_session_list wire target；旧 binary 会设置 ANUREO_SESSION_LIST_EXPECT_LEGACY=1，只验证 list-global fallback 与标准 list；可用 -TestName e2e_mega 显式运行完整流程（e2e target 仅是 harness 根）。每次按 binary 保存 log 并生成包含 binary、expectedMode、时间、exit code、实际 test count、OS/架构、PowerShell 版本和路径的 manifest.json；若 target 执行零测试，runner 会失败而不会假绿；它不替代真实 Desk 版本组合验收。

完整 e2e_mega 仍可能在 session/prompt 前受既有模型解析环境影响；默认的无模型 target 不受该外部依赖影响。.github/workflows/session-list-compat.yml 会在 Ubuntu/macOS/Windows 构建独立 binary、运行该 target，校验 manifest 的模式、测试数、退出码、binary SHA-256、文件大小和 OS/架构字段，并上传 manifest/log 作为跨平台 wire 证据。

Desk acp-event-source 会按 sessionId/id 合并同一 session 的排队事件，保留跨 session 相对顺序；无 session key 的队列最多 256 条，超出部分依赖 owner-wide authoritative resync 修复。关闭事件源时会清空 queue/index，防止 runtime switch 后旧事件泄漏。

session-list 组合回归已固化为 packages/ui 的 bun run test:session（内部使用 Bun --isolate），当前 12 个相关文件共 65/65 通过；普通多文件运行会受到 Bun 全局 module mock 污染，不能作为组合门禁。

.github/workflows/test.yml 新增独立 session-list-ui job，在 Ubuntu 上执行同一个 bun run test:session，与全量 ui-tests 分离。
